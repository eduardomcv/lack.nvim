INTRODUCTION                                                     *lack.nvim*

lack.nvim is a thin declarative wrapper around |vim.pack.add()|. It adds Git
source shorthand and visible nested dependencies, then sends one deduplicated,
dependency-ordered plugin list to Neovim's native package manager.

Requirements: Neovim 0.12 or newer and Git. |vim.pack| is experimental, so its
API may change between Neovim releases.

===============================================================================
INSTALLATION                                              *lack-installation*

Add lack.nvim near the beginning of init.lua. The explicit `load = true` makes
the module available immediately during startup: >lua

    vim.pack.add({
      "https://github.com/eduardomcv/lack.nvim",
    }, {
      load = true,
    })

    local lack = require("lack")
<
To stay on a specific release, set `version` to a published tag: >lua

    vim.pack.add({
      {
        src = "https://github.com/eduardomcv/lack.nvim",
        version = "v0.1.0",
      },
    }, {
      load = true,
    })

    local lack = require("lack")
<
Use a range instead to allow compatible `0.1.x` updates: >lua

    version = vim.version.range("~0.1.0")
<
===============================================================================
USAGE                                                          *lack-usage*

The module is a callable table: >lua

    lack(specs, opts)
    lack.setup(opts)
<
Declare plugins and configure them with ordinary Lua: >lua

    lack({
      {
        "nvim-telescope/telescope.nvim",
        dependencies = {
          "nvim-lua/plenary.nvim",
        },
      },
    })

    require("telescope").setup({})
<
Each lack() invocation calls `vim.pack.add(resolved_plugins, opts)` exactly once.
Native installation, loading, updates, removal, and lockfile behavior are not
changed.

===============================================================================
SETUP                                                         *lack.setup()*

The default source prefix is `https://github.com/`. Set another prefix before
declaring plugins: >lua

    lack.setup({
      repository = "https://gitlab.com/",
    })
<
Trailing slashes are normalized to one slash. `repository` must be a non-empty
string.

===============================================================================
GLOBAL                                                          *lack-global*

`setup()` accepts a `global` option that exposes the callable module without
an explicit require(): >lua

    lack.setup({
      global = true,
    })

    lack({ "owner/plugin" })
<
`global` accepts a boolean, a string, or nil:

    true      registers the module as `lack`, matching the plugin name.
    "name"    registers the module under that name instead. It must be a
              valid Lua identifier.
    false     disables the alias.
    nil       disables the alias. This is also the default.

To use a different name, such as `use`, pass it as a string: >lua

    require("lack").setup({
      global = "use",
    })

    use({ "owner/plugin" })
<
Setup fails, leaving the previous alias and repository unchanged, if the
requested name is already defined by something other than lack.nvim, even
if that value is `false`.
Renaming or disabling the alias only clears it if lack.nvim still owns it.

Because the alias is created at runtime, LuaLS cannot infer its type.
Declare it alongside setup() to get completion and diagnostics: >lua

    require("lack").setup({
      global = "use",
    })

    ---@type lack.Module
    _G.use = require("lack")
<
`lack.Module` resolves only when lack.nvim's lua directory is on LuaLS's
workspace.library.

===============================================================================
SPECIFICATIONS                                         *lack-specifications*

These forms use the same source-resolution path: >lua

    "owner/plugin"
    { "owner/plugin" }
    { src = "owner/plugin" }
<
`src` takes precedence if both `src` and a positional source are present.

Sources using `scheme://` or SCP-style `user@host:path` syntax pass through
unchanged. Every other source is prefixed with the configured repository.

Native fields such as `name`, `version`, and `data` are forwarded unchanged.
Call options are passed directly as the second argument to |vim.pack.add()|: >lua

    lack({
      {
        "owner/plugin",
        version = "v1.2.3",
      },
    }, {
      confirm = false,
    })
<
Other fields are forwarded, but lack.nvim does not execute lazy.nvim-style
`config`, `init`, `opts`, or build hooks.

===============================================================================
DEPENDENCIES                                             *lack-dependencies*

Specifications may contain recursive `dependencies` lists: >lua

    lack({
      {
        "NeogitOrg/neogit",
        dependencies = {
          "nvim-lua/plenary.nvim",
          {
            "sindrets/diffview.nvim",
            dependencies = {
              "nvim-lua/plenary.nvim",
            },
          },
        },
      },
    })
<
lack.nvim gathers every dependency relationship and groups plugins by their
effective native name. Explicit names and source-derived names use their final
path component. A trailing `.git` is removed from source-derived names.

Each plugin is emitted once. Dependencies appear before dependents, while
independent plugins retain declaration order where the graph permits it.
Dependencies from every duplicate occurrence contribute to the graph.

A dependency cycle raises a `lack:` error before |vim.pack.add()| is called.
The error includes the source chain involved.

===============================================================================
CONFLICTS                                                   *lack-conflicts*

The first occurrence of a plugin supplies its fields and stable position.
Conflicting resolved sources raise a `lack:` error before |vim.pack.add()| is
called.

Versions merge regardless of declaration order:

    - A missing version means "any" and never conflicts with an explicit
      version.
    - Two |vim.version.range()| values merge into their intersection.
    - A semver pin found inside a declared range wins over the range.
    - A resolved source conflict, disjoint ranges, a pin outside a declared
      range, or a range paired with a non-semver version (a branch or
      commit) all raise a `lack:` error before |vim.pack.add()| is called.

Version merging only applies within a single lack() call. If a plugin is
already active with a different version from an earlier call in the same
session, |vim.pack| silently keeps the first call's version; lack.nvim emits
a |vim.notify()| warning in that case so the inconsistency is visible.
Collect every declaration into one lack() call to resolve versions globally
instead.

===============================================================================
SCOPE                                                           *lack-scope*

lack.nvim intentionally provides only declaration shorthand and dependency
collection. It does not provide lazy loading, configuration execution,
commands, user interfaces, build orchestration, version consolidation across
separate lack()/|vim.pack.add()| calls (lack.nvim only warns; see
|lack-conflicts|), its own lockfile, updates, removal, or automatic bootstrap
behavior.

==============================================================================
VERSIONING                                                *lack-versioning*

lack.nvim uses Semantic Versioning and publishes releases as
`vMAJOR.MINOR.PATCH` tags. Published tags are immutable. Before `1.0.0`,
compatible fixes and additions increment the patch version, while breaking
changes increment the minor version. From `1.0.0` onward, standard Semantic
Versioning applies.

Breaking changes include incompatible changes to documented configuration or
behavior and increases to the minimum supported Neovim version. User-visible
changes and migration guidance are recorded in CHANGELOG.md.
